# 项目维护文档

更新日期: 2026-10-23. 本文为环境、运维和交付的唯一操作入口. [项目开发文档](项目开发文档.md)记录实现与验证状态, [项目规范文档](项目规范文档.md)规定操作边界, [功能使用文档](功能使用文档.md)面向业务人员.

## 当前状态与操作边界

本项目当前未发布、未上线, 本机MySQL和Redis均为可丢弃的开发数据. 本地启动使用当前配置和初始化源码; 账号凭据不匹配、缺表或结构过旧时自动重建本项目MySQL/Redis开发卷并重试一次, 不迁移或保留旧开发数据. 仅检查归属明确的两个开发卷, 保留上传素材卷, 不操作其他项目. 不能确认归属时停止, 不猜测卷名.

本地脚本不用于承载真实数据的上线环境. 上线并产生真实数据后, 才按单独确认的备份、恢复和增量迁移方案管理数据. 历史测试或交接记录不覆盖本节当前开发规则. 构建不启动容器; 环境构建与启动由用户执行, 代码修改不能冒充真实环境验收.

## 新建开发环境

1. 安装并启动Docker及Compose V2, 在仓库根目录操作.
2. Windows先运行`deploy/scripts/build-local-test.cmd`构建镜像, 成功后运行`deploy/scripts/start-local-test.cmd`启动环境; Linux/macOS先运行`./deploy/scripts/dev.sh build`, 再运行`./deploy/scripts/dev.sh start`. 首次创建`deploy/.env`时生成独立随机数据库、Redis和JWT秘密, 不在终端打印.
3. 直接运行正常启动入口. 本地开发库与当前配置或结构不一致时, 脚本按当前规则重建开发卷, 无需找回旧开发库密码或手工迁移.
4. 管理端默认`http://localhost:8888`, 后台路径`/platform-framework`, 商城路径`/platform-framework-api/app/`. 端口由`.env`中的`NGINX_PORT`统一指定.
5. 小程序开发版通过`apps/miniapp/config/environment.js`配置服务地址. 真机无法用localhost访问电脑, 请使用可达的开发服务地址; 体验/正式版必须配置HTTPS并加入微信合法域名.

首次构建会获取镜像和构建依赖, 需要网络和磁盘空间. 本指南不是执行指令记录, 不代表已构建或重启当前机器的容器.

Windows客户只需安装并启动Docker Desktop(Linux容器及Compose V2), 取得完整项目文件后运行构建和启动两个脚本. 所有编译工具及依赖均在容器内下载, 不需要本机安装Git、Node、Java、Maven、pnpm或Codex. 具体流程见本文“联网构建与客户启动”章节.

Windows两个入口职责独立: `deploy/scripts/build-local-test.cmd`委托`deploy/scripts/dev.ps1 -Action build`, 只构建镜像; `deploy/scripts/start-local-test.cmd`委托`deploy/scripts/dev.ps1 -Action start`, 只启动本地镜像并等待就绪. 构建成功后不会自动启动或替换正在运行的容器, 需再运行启动脚本. 直接运行`.\deploy\scripts\dev.ps1`同样只启动. 启动固定使用已准备好的镜像, 镜像缺失或源码摘要不匹配时提示先运行构建脚本. Windows使用构建输入内容的SHA256识别源码, 不依赖Git或dirty标记. `-NoBuild`不改变启动行为, 不能用于build. 不再提供联网/离线切换或传统构建器参数. Linux/macOS同样显式build后start, start不构建或拉取镜像. 两平台通过deploy/build-inputs.txt计算同一文件字节的SHA256标识, 不依赖Git.

## 开发启动失败与自动恢复

MySQL的healthy只表示服务存活, 启动仍校验root和应用账号以及当前表结构. 认证/数据库名错误1044、1045、1049, 缺少基础表或当前结构版本时, Windows和Bash均自动重建本项目的MySQL及Redis开发卷, 按当前.env和初始化SQL重试一次. 这不是旧数据升级流程, 也不会保留历史开发库快照.

普通SQL语法错误、网络连接错误、应用启动失败不触发自动清库; 重建后仍失败时直接返回错误, 不循环重建. 镜像缺失或摘要不符时在启动数据服务前退出, 需先构建镜像. 可通过status/logs查看状态, 不降低健康或结构检查标准来掩盖错误.

重建前读取Compose解析出的卷名并核对项目标签, 读取失败或属于其他项目时停止. 显式手动ResetData仍支持人工确认; 正常启动中的开发自动恢复使用已确认的可丢弃数据规则, 不重复询问是否保留开发数据. 上传素材卷不参与数据库/缓存恢复.

## 上线后的数据库维护

本项目尚未上线, 当前不执行生产数据库迁移、历史数据兼容或备份恢复流程. 上线后有真实数据时, 再根据正式版本、实际备份和恢复验证制定增量迁移计划; 不将本地可丢弃数据的重建脚本用于真实数据环境.

## 配置与访问边界

- 数据库和Redis只绑定宿主127.0.0.1, 应用容器通过内部服务名访问. 生产网络仍应由部署者限制外部入口并提供HTTPS.
- 微信小程序、公众号、支付的变量通过Compose共享环境块统一传入两个后端. 变量为空表示未配置, 不能视为支付已就绪.
- `WX_PAY_APPID`必须与实际小程序应用匹配; 预支付使用当前用户`maOpenid`. 回调地址必须是支付平台可以访问的真实地址.
- 支付证书放置于私有`deploy/secrets/apiclient_cert.p12`, 只读挂载给后端. 证书不上传图片库、不放入Nginx静态目录.
- 本地图片上传限制5MB和2000万像素, JPEG/PNG/GIF会重新编码为PNG. Nginx请求体上限6MB. SVG、HTML和证书不通过图片接口托管.
- 管理端使用同源接口地址. 小程序体验/正式环境不读取本机storage中的API覆盖值.
- 应用对象缓存切换到`caratcraft:v2:`命名空间, 旧缓存保留并自然过期, 购买上下文需要重新建立. 不执行`FLUSHALL`或删除其他应用缓存.

| 操作 | Windows | Linux/macOS |
|---|---|---|
| 构建镜像 | `deploy/scripts/build-local-test.cmd` | `./deploy/scripts/dev.sh build` |
| 查看状态 | `.\deploy\scripts\dev.ps1 status` | `./deploy/scripts/dev.sh status` |
| 查看日志 | `.\deploy\scripts\dev.ps1 logs` | `./deploy/scripts/dev.sh logs` |
| 启动 | `deploy/scripts/start-local-test.cmd` | `./deploy/scripts/dev.sh` |
| 重启 | `.\deploy\scripts\dev.ps1 restart` | `./deploy/scripts/dev.sh restart` |
| 停止 | `.\deploy\scripts\dev.ps1 stop` | `./deploy/scripts/dev.sh stop` |
| 重建可丢弃测试数据 | `.\deploy\scripts\dev.ps1 -ResetData` | `./deploy/scripts/dev.sh --reset-data` |

重置仅删除当前项目明确解析出的MySQL与Redis卷, 上传图片卷保留, 并要求输入确认词. Bash重置功能需要Python3解析Compose配置; 脚本不会猜测卷名或删除其他项目的数据.

内部`/internal/health/live`只检查应用HTTP存活; `ready`检查数据库、迁移结构/台账和Redis, 失败返回503. Nginx不公开内部探针. Windows和Linux/macOS构建标识均由deploy/build-inputs.txt选定输入内容的SHA256生成, 不依赖Git版本标识. `healthy`也不等同于微信支付、短信或真机业务已经验证.

## 联网构建与客户启动

### 客户准备

取得完整项目源码包并解压到本地目录, 安装Docker Desktop并启动Linux容器引擎, 确保包含Compose V2. Windows使用系统自带的PowerShell执行脚本, 无需Git、Node、Java、Maven、pnpm或Codex. 项目自带源码、Dockerfile、初始化SQL和公开配置模板是交付包的一部分, 客户无需另行准备依赖缓存、node_modules、JAR或dist.

### 第一步: 构建环境

进入项目的`deploy/scripts/`目录, 双击`build-local-test.cmd`, 无需附加参数:

1. 检查Docker命令、Compose及Docker服务是否可用, 计算构建输入的SHA256.
2. 从`m.daocloud.io/docker.io/library/`拉取`mysql:8.0.36`及`redis:7.2-alpine`, 任何下载失败均立即中止.
3. 执行Compose构建并传入`--pull --no-cache`, 联网获取`maven:3.9.11-eclipse-temurin-21`、`eclipse-temurin:21-jre`、`node:24-alpine`和`nginx:1.27-alpine`. 四个构建镜像同样使用`m.daocloud.io/docker.io/library/`前缀, 避免直接连接Docker Hub认证服务. Maven依赖使用`https://maven.aliyun.com/repository/public`, pnpm及前端依赖使用`https://registry.npmmirror.com`, 全部在构建容器内下载, pnpm按原锁文件安装. 不沿用旧构建层跳过依赖安装.
4. 构建成功后生成`carat-craft-backend:local`和`carat-craft-admin-ui:local`, 提示运行启动脚本. 下载或编译失败保留原始错误并返回非零退出码, 不继续启动, 修复问题后重新运行本脚本.

构建只使用随包公开配置模板, 不读取本机运行密钥或生成私有配置. Docker构建上下文排除本机依赖、target、dist、私有环境文件、application-local配置和证书目录. 不提供离线缓存构建、Codex运行时查找或手工指定Maven缓存的入口. 客户不需要以VPN或手动输入代理命令为前提; 网络必须能够访问m.daocloud.io、maven.aliyun.com及registry.npmmirror.com, 公共镜像服务仍可能限流或故障. 不自动切回海外源, 也不改系统或Docker代理; 如果此前为排障手动设置了代理, 可在Docker Desktop按自身网络情况选择No proxy, 不需要修改VPN软件. 网络必须能够访问上述镜像仓库及Maven/npm依赖仓库; 后续构建也会访问网络. Docker仍可保留已有镜像与下载层, 脚本不会清理其他项目的缓存.

### 第二步: 启动服务

构建成功后在同一`deploy/scripts/`目录双击`start-local-test.cmd`:

1. 首次运行自动从公开模板生成`deploy/.env`, 为数据库、Redis和JWT生成独立随机秘密, 不在终端输出秘密值; 已有配置保持不变. Windows模板、配置校验及端口读取均显式使用UTF-8, 兼容Windows PowerShell5.1和PowerShell7; 无BOM UTF-8文件不按系统ANSI编码解释. 模板中四项密钥必须各有且只有一条, 否则在创建配置前中止. 缺项和不足24字符分别报错, 此阶段尚未连接数据库. 配置重新生成不会就地修改旧库密码; 正常启动会识别失配并按开发规则重建两个开发卷.
2. 检查四个运行镜像是否存在, 并核对应用镜像的源码摘要. 摘要涵盖前后端源码、依赖声明、Dockerfile、初始化SQL、公开模板、许可及部署配置, 排除本机依赖、生成目录、私人配置和仅在宿主机执行的deploy/scripts. 清单自身固定LF; 修改启动脚本不会单独触发镜像重建, 修改应用、Dockerfile、SQL等镜像相关输入仍须重建. ZIP解压使用同一规则, 无需Git历史.
3. 启动MySQL和Redis并等待就绪. 空数据卷执行当前初始化SQL; 已有开发库的凭据、表结构或版本不匹配时自动重建一次.
4. 启动两个后端和Nginx管理端, 等待健康检查通过后显示访问地址, 管理端默认为`http://localhost:8888`.

启动明确使用`--no-build --pull never`, 不临时构建或下载镜像. 缺失镜像时返回第一步; 源码变化后也应先重新构建. 首次初始化失败、旧库缺迁移或健康检查失败时显示诊断并返回失败, 不将部分启动报告为成功. 端口占用等问题按Docker原始错误排查. 镜像检查失败时直接报告缺镜像或摘要不匹配, 不检查尚未创建的容器. 运行阶段的状态诊断仅提供补充信息; 容器不存在、元数据读取失败或诊断异常不得覆盖原始错误. 本次将宿主机脚本移出构建输入后需要重新构建一次, 此后使用修正后的唯一摘要规则, 不绕过校验.

当前本地开发数据不要求保留或增量升级; 上线后真实数据按“上线后的数据库维护”边界另行制定方案. 微信登录、真实支付和AI等验收仍需要实际平台账号及配置, 不因本地环境启动成功而视为通过. 前次环境入口提交仅修改脚本和文档, 当时未执行测试、镜像下载、真实构建或服务启动验收; 本轮结构验证见开发文档第7节.

以下命令列出入口, 执行数据库和Redis测试前须确认目标为随机独立测试环境. 不向真实微信、支付、短信、邮件或AI发送测试请求.

```powershell

node --test @tests
# 交付工具及文档回归. 摘要对照需提供真实Bash路径, 未设置时明确跳过.

# 创建随机隔离库, 只运行根初始化及全部V版本.
```

测试失败先修复并重跑受影响用例, 最终确认完整验证. 格式整理不需要无意义地新建大量测试; 契约和事务修改必须验证成功、失败、恢复和归属边界.
