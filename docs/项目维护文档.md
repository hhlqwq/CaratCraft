# 项目维护文档

更新日期: 2026-11-18. 本文为环境、运维和交付的唯一操作入口. [项目开发文档](项目开发文档.md)记录实现与验证状态, [项目规范文档](项目规范文档.md)规定操作边界, [功能使用文档](功能使用文档.md)面向业务人员.

## 当前状态与操作边界

小程序验收状态以开发文档第8节及[三端验收矩阵](资料/三端验收矩阵.json)为准. 旧归档和已有运行实例不能作为最新源码验收. 不为检查代码强行改变微信工具安全设置、重开窗口或读取登录令牌; 编译、模拟器、真机及真实支付分别记录.

标准启动只检查与使用已有数据卷. 数据库认证、结构或版本异常时终止启动, 由操作者按独立初始化、升级或重置流程处理.

正式环境及须保留的验收环境采用经确认的备份、恢复和更新步骤. 构建、部署与真实平台验收分别记录.

## 上线前末轮验收

1. 保留现有验收数据. 先核对目标机器、Compose项目、MySQL卷及上传卷, 记录结构版本、商品/SKU、DIY、社区、协议和交易基线. 更新前备份MySQL与上传文件, 在隔离环境验证可恢复. 保留数据的环境禁止使用 reset-db 或删除数据卷. 初始化SQL只供新空库使用.
2. 确定候选版本. 记录Git提交、镜像源码摘要和小程序构建版本, 保留可回滚的上一个应用版本. 经确认后仅替换需要更新的应用服务, 保留数据卷. 核对运行镜像、管理首页、商品主图和小程序素材均能打开, 重新对照更新前的数据库基线. 演示商品与社区素材仅在验收环境使用.
3. 配置验收渠道. 部署人员提供体验版和正式版各自的可访问HTTPS API地址, 小程序发布人员配置环境地址及对应微信后台域名. 面向验收的环境核对微信登录、支付、退款和短信所需配置及授权. 正式商户补齐客服、品牌、协议主体、真实商品和DIY工艺. 正式库发布前通过受控流程装入已确认的生产目录和初始库存, 核验可售数据.
4. 先走一笔普通商品单, 再走一笔DIY单. 在体验版真机验证登录及协议、图片、选规格和地址、订单创建、付款查单和后台待办. 普通单覆盖发货、收货与评价, 另用业务允许的订单核对退款结果和库存回补. DIY单覆盖选择材料、报价、保存重开、下单冻结、工单审核、制作和质检. 社区用测试账号验证发布、审核、展示和点赞. 短信使用自有测试号码记录收码和绑定结果.
5. 记录验收结果. 保存应用版本、环境、用例结果和脱敏后的订单/退款单号, 核对平台状态、后台状态与库存. 发布前确认账户权限、备份恢复及回滚. 涉及正式交易、短信、部署切换或业务库变更, 由相应负责人确认后执行.

菜单路径见[商家后台快速入门](功能使用文档.md#商家后台快速入门).

2026-11-18本机已完成保留数据的应用更新. 使用现有候选镜像, 通过Compose按服务更新 `platform-admin`、`platform-api` 和 `nginx`, 使用 `--no-deps --no-build --pull never`. MySQL、Redis及上传卷留在原位置. 备份及回退配置保存在工作区忽略目录 `.tools/integration/launch-2026-11-18/`, 数据备份子目录有限定的文件权限. 数据库恢复在隔离环境完成, 应用回退镜像的主要文件哈希已核对. 本机部署及公开接口实测见[三端验收矩阵](资料/三端验收矩阵.json).

## 订单权限发布

空库由 `database/init` 初始化. 已有环境使用以下增量脚本, 先在脱敏备份上试跑, 由环境负责人确认授权、备份和维护窗口后再执行. 生产脚本应显式连接审批指定的库, 使用 `mysql --default-character-set=utf8mb4`, 保留每次执行结果.

已有库升级后端前, 先核对岗位权限增量是否已完成. `CC_SCHEMA_VERSION=1` 只代表完成基础初始化. 若登录返回 HTTP 500 且后台报 `Unknown column 'LAST_LOGIN_AT'`, 或订单任务报 `Unknown column 'SCOPE_ORG_NO'`, 先备份并按下表升级现有库. 验证通过后复查登录、业务记录和角色绑定, 保留原初始化数据.

| 顺序 | 脚本 | 核对项 |
| --- | --- | --- |
| 1 | [precheck.sql](../database/upgrade/admin-jobs/precheck.sql) | 只读盘点角色、员工、旧订单权限、通配、机构绑定和多角色叠加. 对照定义核查冲突. |
| 2 | [apply.sql](../database/upgrade/admin-jobs/apply.sql) | 幂等补齐阶段一、阶段二权限节点及结构, 创建缺失预设岗位. 核对原有角色授权不变, 新岗位无员工绑定. MySQL DDL 会逐项提交, 失败需核对输出后处理冲突并续跑. |
| 3 | [assign-ownership.sql](../database/upgrade/admin-jobs/assign-ownership.sql) | 负责人按单条已核实的商品、订单、反馈和社区映射填写脚本, 在同一客户端会话校验并回填. 空模板保持现状, 冲突映射会使该批事务回滚. |
| 4 | [verify.sql](../database/upgrade/admin-jobs/verify.sql) | 核对节点父级与权限键、岗位及人员绑定、机构范围和未归属记录. 保存上线预检与授权后的两份输出. |
| 回退 | [rollback.sql](../database/upgrade/admin-jobs/rollback.sql) | 与原版本应用配套. 核对未执行的审核意见和退款队列, 停写后先备份现状. 遇已授权、分配机构或已修改的模板先人工核对. 脚本仅回退权限节点和未启用模板, 保留新增结构、历史归属及操作记录. |

上线前由业务与权限负责人逐项确认.

- 指定岗位负责的已启用工作室, 对历史业务逐条确认归属. 历史商品不可见时, 先对照商品编号、SKU、库存和图片来源, 备份后把经批准的精确编号填入 [assign-ownership.sql](../database/upgrade/admin-jobs/assign-ownership.sql) 的临时映射. 旧备份独有的商品先在隔离库检查主表、SKU、图库和素材校验值, 仅用已批准的新增记录名单恢复. 部署时设置 `CARATCRAFT_DEFAULT_BUSINESS_ORG` 为实际接收新商城订单、反馈及社区内容的启用机构编码. 未归属记录由获准执行只读预检的运维人员盘点. 切换前后分别核对商品运营、履约、客服、退款和社区待处理数据.
- 旧 `mall:order:update` 仅作为盘点线索. 确认负责改价的人员后手动分配 `mall:order:price:update`. 履约使用 `mall:order:ship`; 客服使用 `mall:aftersale:*` 对应的单项授权; 退款列表、审核、执行、重试和对账按职责分配五个明确权限. 核对所有历史通配授权和叠加岗位.
- 核对商家管理员所属工作室和受委派的岗位权限, 验证平台账号人工恢复、账号启停、初始凭据交付渠道和审计检查人.
- 用不同岗位普通测试账号分别核对工作台、队列、详情和直接 API 的允许与拒绝. 使用隔离库和退款渠道替身执行退款回归.

```powershell
python tests/integration/verify-admin-jobs-upgrade.py
python tests/integration/run-community-regressions.py --native-workspace --package
```

第一条以第一阶段初始化新建临时 MySQL, 验证实际升级、重复执行、显式归属回填及回滚. 第二条创建随机隔离 MySQL 和 Redis, 在管理端随机回环端口运行 Shiro 权限 HTTP 用例. 离线构建可传入配套的 `--maven-cache` 和 `--settings`. 账号登录测试使用隔离图片验证码; 员工找回及管理员重置的部署要求见“员工密码更新”.

管理端界面回归使用已构建的管理端 `dist` 和本地 Edge. 如果产物位于其他目录, 通过 `CARATCRAFT_ADMIN_DIST` 指定路径. Playwright 独立安装时设置 `CARATCRAFT_NODE_MODULES` 指向依赖目录. Node 健康探针可通过 `CARATCRAFT_JAVA_DOCKER=true` 使用已缓存的 Java 镜像, `CARATCRAFT_TEST_TEMP` 可指定独立测试夹具目录.

```powershell
$tests = @(Get-ChildItem tests/node -Filter '*.cjs' | Select-Object -ExpandProperty FullName)
node --test @tests
node tests/browser/verify-commerce-browser.cjs
```

## 员工密码更新

已有验收库先备份, 在隔离副本试跑 [员工密码增量 SQL](../database/upgrade/staff-password/apply.sql). 在受控窗口仅执行该增量, 保留已有账号、角色和密码. 更新应用后检查只能通过本人改密或退出接口使用临时会话. 新库使用当前初始化脚本. 回退应用前先核对并停用仍为临时密码的账号, 保留新增列和凭据变更记录.

邮箱和短信找回默认关闭, 按已实测渠道设置 `CARATCRAFT_STAFF_RECOVERY_EMAIL_ENABLED` 或 `CARATCRAFT_STAFF_RECOVERY_SMS_ENABLED`. 邮件需要 SMTP 主机、端口、发件账号及密钥, 短信复用现有签名和六位码模板. 在隔离环境用独立账号核对收码、过期、重复使用、旧会话撤销和管理员重置. 真实渠道未验时继续用管理员办理重置.

## 商品问答与新人活动升级

已有本地库的商品问答表和评价商家回复字段由[本地安全结构增量](#本地安全结构增量)补齐. 旧常见问题、评价正文均保留. 新人券属于商家可选活动, 已有库按需在优惠券列表配置; [新人活动模板SQL](../database/upgrade/welcome-coupon/apply.sql)仅供独立人工维护. 保留现有券配置与已发券, 启动时不执行发券或活动模板SQL.

## 三级账号升级与恢复

空库初始化只写入禁用且无密码的 `USER_ID=1`. 独立生成至少 144 位随机数, 以 24 到 32 位 URL 安全文本放入 `deploy/secrets/platform-bootstrap.txt`. 设置 `CARATCRAFT_SUPER_ADMIN_BOOTSTRAP_FILE=/run/secrets/platform-bootstrap.txt`, 启动管理应用后临时凭据在 30 分钟内只能兑换一次改密会话. 首次改密后移除引导配置和私有文件. 配置只在账号封存且尚无密码时生效. 遗失凭据或会话须由授权运维人员核验, 经确认后运行 [reseal-platform.sql](../database/upgrade/account-tiers/reseal-platform.sql), 再使用全新私有引导文件.

开户前由运维确认并准备唯一启用工作室, 令 `CARATCRAFT_DEFAULT_BUSINESS_ORG` 指向它. 已有环境先执行[账号只读预检](../database/upgrade/account-tiers/precheck.sql). 历史账号层级和工作室逐个确认, 并单独盘点空归属商品、订单、反馈及社区内容. 账号升级不回填业务记录. 旧库可能已有结构版本1但缺少增量字段. 标准启动按[字段清单](../deploy/schema-preflight.sql)报告缺项, 并拒绝启动存在未映射账号的应用.

已有库在验证备份及停写后, 由业务数据库操作者在同一会话准备 `CREATE TEMPORARY TABLE cc_tier_mapping (USER_ID varchar(32) PRIMARY KEY, ACCOUNT_TYPE varchar(16) NOT NULL, ORG_NO varchar(32))`, 写入已批准的完整映射并设置 `@cc_default_org` 和 `@cc_confirm_account_tiers='APPLY_ACCOUNT_TIERS'`. 执行 [apply.sql](../database/upgrade/account-tiers/apply.sql) 后核对层级和会话撤销, 再为已封存的平台账号签发安全凭据. 业务库实际执行需要另行确认.

回退前确认平台及商家管理员已完成临时改密且无个人授权, 设置 `@cc_confirm_account_tier_rollback='ROLLBACK_ACCOUNT_TIERS'` 后运行 [rollback.sql](../database/upgrade/account-tiers/rollback.sql). 有个人授权、未消费的临时凭据或 DDL 部分失败时, 使用受控备份恢复流程并复验账号边界. 回退旧应用会恢复其原有的权限语义, 仅在已批准的停写窗口操作.

## 新建开发环境

1. 从 GitHub 克隆 `hhlqwq/CaratCraft` 的 `main`, 核对 `git status --short --branch` 和 `git rev-parse HEAD`. 安装并启动 Docker Desktop 的 Linux 容器及 Compose V2. 使用小程序配置和诊断工具时另装 Node.js 22.13 至 24.x.
2. Windows 执行 `powershell -File deploy/scripts/dev.ps1 -Action configure`, Linux/macOS 执行 `./deploy/scripts/dev.sh configure`. 入口从公开模板创建本机私有配置, 四项运行密钥随机生成. 已有 .env 保留原值, 对照模板补充缺失的键, 保留与已有数据库匹配的凭据.
3. 按下表配置环境. 用 `build-local-test.cmd` 或 `dev.sh build` 构建, 已有数据环境跳过初始化. 新环境显式执行 `dev.ps1 -Action init-db` 或 `dev.sh init-db`, SQL 仅作用于本次新卷. 初始化成功后用 `start-local-test.cmd` 或 `dev.sh start` 启动.
4. 首次导入正式小程序时, 在 `apps/miniapp` 将 `project.config.example.json` 复制为 `project.config.json`, 按需把游客 AppID 换成自己的 AppID. 若从仍跟踪该文件的旧版本升级, 拉取前备份本机配置, 拉取后放回原处. 本机已有配置时直接使用. 执行 `dev.ps1 -Action miniapp` 或 `dev.sh miniapp` 生成 API 地址配置, 再用微信开发者工具打开 `apps/miniapp`. 如果切换检出后缺少 `apps/miniapp/config/environment.local.js`, 直接重新运行小程序配置生成命令. 切换环境或网卡地址时, 更新 .env 后重新生成并编译.
5. Windows 运行 `tools/dev-env-check.cmd`, Linux/macOS 运行 `./deploy/scripts/dev.sh diagnose`. 管理端默认访问 `http://localhost:8888`. 在微信开发者工具网络面板核对首页和商品的现有 POST 接口, 以及社区和 DIY 的公开 GET 接口.

### 旧配置升级

已有 `deploy/.env` 使用 `dev.ps1 -Action check-config` 或 `dev.sh check-config` 只读盘点. 输出包括缺失的可选项及阻断启动的键, 不显示值. 使用 `repair-config` 显式追加公开模板标记的安全缺项, 保留现有键、注释、空值和换行. 已有局域网地址但缺模式、默认端口与现值冲突、数据库名及用户、密码和 JWT 密钥由运维核对. `configure` 只为不存在的文件生成新环境配置. 标准启动仍独立执行校验, 保留已经存在的数据库、Redis 及上传卷.

### 环境配置来源与优先级

| 配置 | 唯一入口及解析顺序 |
| --- | --- |
| 本机运行 | `deploy/.env` 由脚本显式传给固定 Compose 项目 `platform-wxshop`. 脚本清除模板中的同名宿主变量. 模板用于创建配置和公开构建, 不能覆盖已有文件. |
| 应用容器 | Compose 将 `MYSQL_APP_USER`、`MYSQL_APP_PASSWORD` 映射为 Spring 的 MYSQL_USERNAME / MYSQL_PASSWORD, MySQL 和 Redis 通过服务名与容器端口互连. 宿主端口只影响外部访问. Spring 使用 docker profile, 部署变量覆盖 YAML 对应占位值. |
| 管理网页和上传 | 管理端默认同源访问 Nginx 的 `/platform-framework`. Nginx 转发商城 `/platform-framework-api`, 使用 Docker DNS 解析后端服务, 并通过 `/upload` 提供共享持久卷中的图片和视频. |
| 微信开发版 local | `CARATCRAFT_ENV=local`, 开发地址默认为 `http://127.0.0.1:<NGINX_PORT>`, 可通过 `MINIAPP_LOCAL_ORIGIN` 显式指定. 回环地址只用于本机, 真机使用开发机可达的地址. |
| 微信开发版 lan | `CARATCRAFT_ENV=lan`, 必填 `MINIAPP_LAN_ORIGIN`, 为当前网卡可达站点源, 禁止回环地址. 按微信网络规则使用符合要求的地址, 保持项目域名校验启用. |
| 微信体验版、正式版 | 分别从 `MINIAPP_TRIAL_ORIGIN` 和 `MINIAPP_PRODUCTION_ORIGIN` 生成, 与 local、lan 独立. 需要 HTTPS、公信证书、可解析域名和微信公众平台登记的 request 合法域名. `production` 仅生成发布配置, 开发启动入口会拒绝此模式. |
| 小程序最终地址 | 工具追加固定 `/platform-framework-api/app/` 并生成 Git 忽略的 `apps/miniapp/config/environment.local.js`. 运行时只读取当前微信发布环境对应项, 缺失立即报错. 设备缓存中的旧地址不参与解析. |
| 支付、短信及邮箱 | 微信和 SMTP 参数按 .env 模板填写. 短信供应商凭据及模板沿用数据库配置. 支付证书放在私有 `deploy/secrets/`, 只读挂载. 小程序生成配置不包含这些秘密. |

### 独立数据操作

| 操作 | Windows | Linux/macOS |
| --- | --- | --- |
| 空库初始化 | `dev.ps1 -Action init-db` | `dev.sh init-db` |
| 既有库增量 | `dev.ps1 -Action upgrade-db -Upgrade staff-password` | `dev.sh upgrade-db staff-password` |
| 可丢弃数据重置 | `dev.ps1 -Action reset-db` | `dev.sh reset-db` |

人工增量先核对目标库、备份和对应 SQL, 输入 `UPGRADE_DB` 才执行. 重置只接受输入 `RESET_DATA`, 校验卷归属并保留上传卷. 重置完成后如需新数据, 再单独执行初始化. 标准启动只接受项目已有的数据卷, MySQL 凭据、结构或版本有误就停止. 数据服务已运行时保持现有容器, 应用通过自身健康检查验证当前凭据.

### 本地安全结构增量

标准启动只读取[显式迁移清单](../database/upgrade/local/manifest.txt). 清单按四位序号递增, 每项指向同一目录内的 check.sql 和 apply.sql, 只登记经过审核、能在应用持续运行时安全执行的加法结构增量. check.sql 只读检查并设置 @cc_compatible 和 @cc_complete, apply.sql 依据 @cc_need_apply 幂等补齐结构. 账号层级、权限、归属、密码、营销种子、材料数据和回退脚本保留人工入口.

MySQL 在同一连接中加锁并写入 CC_SCHEMA_MIGRATION, 记录迁移编号、两个脚本的 SHA256 指纹及完成时间, 与软件版本、Git SHA、空库 CC_SCHEMA_VERSION 标识分离. 独立 init-db 在核对完整的新库结构后登记已有的迁移基线, 不重放旧版 DDL. 启动先读已完成编号, 获锁后复核完成状态与所有已登记指纹. 已完成的历史脚本只核对指纹, 待执行的增量才运行自身的前后置结构检查. 已登记脚本保持不可变, 后续调整新增编号. 遇到未知记录、指纹不符、同名结构异常或锁超时, 停止应用更新并报告数据库迁移阶段.

MySQL DDL 分步提交. 中断后查看迁移记录的 applied_at 和实际结构, 初次执行或未完成记录允许已验证的结构继续补齐. 待执行增量完成后按[current-schema.sql](../database/upgrade/local/current-schema.sql)检查当前版本所需结构. 发布新迁移时同步更新当前契约; 当前结构失配时停止并人工排查. 保留备份及两类检查结果, 不删除迁移记录来强行绕过校验. 首次更新保留数据的验收环境前先备份.

新增迁移需在真实隔离 MySQL 上验证空库登记、已有缺项、重复启动、部分提交和失败路径. Windows 可运行 `python tests/integration/test-local-migrations.py`, 只使用本机已有 MySQL 镜像和临时容器.

### 构建与失败诊断

按 [构建输入清单](../deploy/build-inputs.txt) 分别对 Java 后端和 Vue/Nginx 计算 SHA256. 源码变更只影响收录该文件的镜像. 小程序 JS/WXML/WXSS 由微信工具独立编译, 仅 Nginx 引用的共享图片影响 Vue/Nginx. 本机配置由 Compose 应用到相关容器. Git SHA 用于追溯, 离线源码包记为 archive. 普通文档、Git 元数据和私有配置不参与镜像摘要. 标准启动先检查各自摘要, 必要时构建, 构建失败保留原容器. 启动仅收敛发生变化的应用配置或镜像, 就绪后核对实际镜像 ID、摘要、服务健康、Nginx 页面、后台根路径的预期 401 和 API 服务根路径的响应. 应用就绪继续使用容器内部探针, 商城或 DIY 的行为单独做业务验证. 脚本输出耗时. 本机需要严格仅使用已有镜像时传入 `-NoBuild` 或 `--no-build`.

Nginx 返回 502 时先核对 upstream、容器健康和实际镜像. request:fail 时对照生成地址、DNS/TLS、微信合法域名和 Nginx 访问日志. 光有健康状态不足以证明微信真机能联网.

## 配置与访问边界

- 数据库和Redis只绑定宿主127.0.0.1, 应用容器通过内部服务名访问. 生产网络仍应由部署者限制外部入口并提供HTTPS.
- 微信小程序、公众号、支付的变量通过Compose共享环境块统一传入两个后端. 变量为空表示未配置, 不能视为支付已就绪.
- APIv3 要求 `WX_PAY_APPID` 与小程序匹配, 另配 `WX_PAY_MCH_ID`、`WX_PAY_MERCHANT_SERIAL_NUMBER`、`WX_PAY_API_V3_KEY`、`WX_PAY_PUBLIC_KEY_ID`、`WX_PAY_NOTIFY_URL`. 私钥和微信支付公钥按[挂载说明](../deploy/secrets/README.md)配置. `WX_PAY_NOTIFY_URL` 指向微信可访问的 HTTPS `/platform-framework-api/app/pay/notify`. 未配置商户凭据时后端仍可启动, 支付入口给出配置缺失提示. 真实商户的证书、微信通知、扣款和退款需单独验收.
- 员工开户依赖 `CARATCRAFT_DEFAULT_BUSINESS_ORG` 指向已启用机构, 开户人在该机构须有员工新增权限. 员工资料编辑保持原归属.
- 本机磁盘上传使用 `/data/uploads` 和 `/upload` 同源地址. 更新应用或重新创建 Nginx 时继续挂载原 `upload-data` 卷. 上线前确认目标环境的持久卷、备份恢复、HTTPS 与微信合法域名. 隔离复测使用 `python tests/integration/run-http-business-chain.py --date 2026-11-18 --storage-only`.
- 微信商户私钥和微信支付公钥通过私有 `deploy/secrets/` 目录只读挂载给后端. 密钥文件不上传图片库、不放入 Nginx 静态目录.
- 本地图片上传限制5MB和2000万像素, JPEG/PNG/GIF会重新编码为PNG. Nginx请求体上限6MB. SVG、HTML和证书不通过图片接口托管.
- 管理端使用同源接口地址. 小程序体验/正式环境不读取本机storage中的API覆盖值.
- 应用对象缓存切换到`caratcraft:v2:`命名空间, 旧缓存保留并自然过期, 购买上下文需要重新建立. 不执行`FLUSHALL`或删除其他应用缓存.

普通JSON入口上限为6MiB, 与Nginx普通请求6m一致; 超限返回413, 格式或编码错误400, 媒体类型不支持415. 文件上传继续使用现有独立上传路径限制, 不经过JSON预读. 微信支付 APIv3 通知在 JSON 校验后保留正文原字节, 供官方 SDK 验签. 代理拒绝与应用拒绝的错误正文可能不同, 排障同时核对HTTP状态及日志.

先按当前源码构建backend两个应用JAR, 再执行python tests/integration/run-http-business-chain.py --date YYYY-MM-DD, 日期使用客户端日期. 入口仅使用已有mysql:8.0.36、redis:7.2-alpine和carat-craft-backend:local镜像, 始终--pull=never; 随机命名的全新MySQL使用tmpfs并执行完整初始化源码, Redis不持久化, 两个最新JAR只读挂载. 服务端口仅随机绑定127.0.0.1, 原业务容器及数据卷不参与. 合成身份在隔离库预置, JWT使用本次随机密钥, 不调用微信、短信、支付或登录验证码服务. 测试执行真实认证器、HTTP Controller、MyBatis、MySQL及Redis, 使用实际小程序SKU模块解析HTTP返回数据. 成功后只将无凭据的检查项写入docs/资料/HTTP业务链路验证.json, 全部专用容器在finally中清理. 这不是对已运行实例的部署验收.

### 职责门禁与回归开关

Check-SourceStyle.ps1会执行Java职责语法树检查. 无宿主机JDK时使用-Docker及已有maven:3.9.11-eclipse-temurin-21镜像; 仅使用JRE会明确失败. 两端和工具ESLint共用中文职责规则, 不维护忽略旧错误的基线. 四项Java规则测试使用合成源码及约定临时目录, 全套Python验证前显式设置CARATCRAFT_JAVA_STYLE_DOCKER=true、CARATCRAFT_TEST_DATE为客户端日期, CARATCRAFT_BASH指向已有Git Bash; 未提供运行时的跳过必须单独记录. 语法树规则只解析源码, 不生成.class或调用业务服务.
