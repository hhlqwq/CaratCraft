# CaratCraft 项目蓝图

## 1. 项目定位

CaratCraft 是面向珠宝定制商家的微信小程序商城。用户可以选择项链基础款、链条、吊坠、材质、长度、刻字和宝石等参数，实时预览并使用微信支付下单。商家在管理后台完成商品配置、价格规则维护、订单审核、生产和发货。

一期以标准化 DIY 项链为边界，采用二维图层合成预览，不提供自由建模、AR 试戴或开放式上传设计稿。所有订单配置均需要生成可追溯的工艺快照。

## 2. 一期业务范围

### 用户端

- 微信授权登录、收货地址、商品浏览、购物车、订单和售后入口。
- 选择链条、吊坠、材质、长度、刻字和宝石，实时预览并询价。
- 保存设计、确认订单、微信支付、订单状态和物流查询。

### 管理端

- 商品、组件、素材、库存和上下架管理。
- 组合兼容性、加价和刻字规则管理。
- 订单审核、补差价、生产工单、质检和发货管理。
- 设计快照、操作日志和基础经营数据查询。

### 一期不包含

- 完整 3D 实时渲染、AR 试戴和 CAD 自动建模。
- 用户自由上传图片或手写稿定制。
- 多商家入驻、分销、直播、拼团和跨境支付。

## 3. 技术决策

| 模块 | 一期方案 | 说明 |
| --- | --- | --- |
| 商城底座 | platform-wxshop | Apache-2.0 许可，含 Java 后端、管理端、uni-app 与原生小程序端。 |
| 用户端 | 原生微信小程序优先 | 保留底座的 wx-mall；DIY 页面使用 Canvas。 |
| 后端 | Spring Boot + MySQL + Redis | 延续底座技术栈，降低支付与订单改造成本。 |
| 管理端 | Vue + Element UI | 复用后台，新增定制商品和生产工单页面。 |
| 图片存储 | 云对象存储 | 保存商品图、透明组件素材和设计成品图。 |
| 支付 | 微信支付小程序支付 | 后端创建支付单、回调验签、订单幂等更新。 |
| DIY 渲染 | 透明图层 + Canvas 2D | 按组件锚点、层级和遮罩合成。 |

二期再评估 Three.js 3D 预览。`CC_CUSTOM_PRODUCT.model_url`、`CC_COMPONENT_OPTION.model_url` 和 `material_params` 已作为 3D 扩展位预留；它需要独立完成模型资产、低端设备降级和材质表现验证，不能以一期交付为前提。当前路线明确不包含 AR 试戴。

## 4. 系统架构

```text
微信小程序
  ├─ 商城页面、DIY Canvas、订单与支付
  └─ HTTPS API
          │
Java API 服务
  ├─ 用户与商品
  ├─ 定制配置校验与价格引擎
  ├─ 订单、支付回调、售后
  └─ 工单与后台管理 API
          │
MySQL ─ Redis ─ 对象存储
          │
Vue 管理后台
  └─ 商品/规则/订单/生产工单
```

### 关键原则

- 前端只做预览，服务端是配置合法性和最终成交价的唯一判定方。
- 订单创建时固化设计 JSON、价格明细、素材版本和预览图；商品改价不得影响历史订单。
- 微信支付回调按支付单号幂等处理，不能重复支付、扣库存或生成工单。
- 定制商品进入制作前允许后台人工审核和补差价，避免工艺限制导致亏损。

## 5. 领域模型与数据表

### 商品配置

| 表名 | 关键字段 | 用途 |
| --- | --- | --- |
| `cc_custom_product` | `product_id`、`template_code`、`enabled` | 标记普通商品是否开启 DIY，以及渲染模板。 |
| `cc_component` | `component_type`、`code`、`base_sku_id`、`status` | 链条、吊坠、宝石等可选组件。 |
| `cc_component_option` | `component_id`、`option_code`、`material`、`price_delta` | 组件具体选项，例如 18K 金、45cm。 |
| `cc_component_asset` | `option_id`、`asset_url`、`z_index`、`anchor_x`、`anchor_y` | 素材、图层顺序和定位信息。 |
| `cc_compatibility_rule` | `source_option_id`、`target_option_id`、`rule_type` | 允许、禁止或强制选择的组件组合。 |
| `cc_price_rule` | `rule_type`、`expression`、`priority` | 长度、刻字、材质、宝石等加价规则。 |

### 用户设计与订单

| 表名 | 关键字段 | 用途 |
| --- | --- | --- |
| `cc_design` | `user_id`、`product_id`、`configuration_json`、`preview_url` | 用户保存的可编辑设计方案。 |
| `cc_design_snapshot` | `design_id`、`configuration_json`、`asset_versions`、`preview_url` | 下单时冻结的设计快照。 |
| `cc_order_customization` | `order_item_id`、`snapshot_id`、`price_breakdown_json` | 订单项与定制快照、价格明细关联。 |
| `cc_production_work_order` | `order_item_id`、`work_order_no`、`status`、`craft_json` | 可供生产执行的工单。 |
| `cc_order_review` | `order_item_id`、`review_status`、`review_note` | 人工审核和补差价记录。 |

> 当前一期简化实现映射：素材与图层信息并入 `CC_COMPONENT_OPTION`（`asset_url`、`z_index`），设计与快照合并为 `CC_DESIGN_SNAPSHOT`（以 `status` 区分 DRAFT/LOCKED/ORDERED），兼容与加价校验暂由报价服务内置逻辑实现。`cc_design`、`cc_component_asset`、`cc_compatibility_rule`、`cc_price_rule`、`cc_order_review` 为二期扩展位，建表脚本见 `_sql/carat_craft_customization.sql`。

### 订单状态

```text
待支付 -> 已支付待审核 -> 待制作 -> 制作中 -> 质检中 -> 待发货 -> 已发货 -> 已完成
                       └-> 待补差价 -> 已支付待审核
已支付待审核/待制作/制作中 -> 售后处理中 -> 已退款或售后完成
```

状态迁移必须由服务端状态机控制，并记录操作人、时间和原因。

## 6. 核心接口清单

| 接口 | 方法 | 作用 |
| --- | --- | --- |
| `/api/custom-products/{id}` | `GET` | 返回定制商品、组件、素材和可展示规则。 |
| `/api/custom-designs/quote` | `POST` | 校验配置并返回服务端计算的价格和错误信息。 |
| `/api/custom-designs` | `POST` | 保存用户设计方案。 |
| `/api/custom-designs/{id}` | `GET` | 获取并继续编辑已保存方案。 |
| `/api/orders/custom` | `POST` | 创建含设计快照的订单，返回支付参数。 |
| `/api/payments/wechat/notify` | `POST` | 接收微信支付回调并幂等更新订单。 |
| `/admin/custom-rules` | `GET/POST/PUT` | 管理组合兼容性与价格规则。 |
| `/admin/production-work-orders` | `GET/PUT` | 查询、分派和更新生产工单。 |

下单接口不接收客户端金额作为可信字段。后端必须重新计算报价，并以当前有效报价创建订单。

## 7. 小程序页面结构

```text
pages/
  home/                 首页
  category/             分类与商品列表
  product/              商品详情
  designer/             DIY 定制器
  designs/              我的设计
  cart/                 购物车
  checkout/             确认订单与支付
  orders/               订单列表与详情
  profile/              个人中心、地址、客服
```

`designer/` 页面按“预览区、价格区、组件选项区、底部操作区”组织。用户每次修改选择后先在本地更新预览，再调用报价接口；报价未返回或校验失败时不允许提交订单。

## 8. DIY 渲染与定价规则

### 渲染规则

1. 以商品模板定义固定画布尺寸、各部件锚点和默认图层顺序。
2. 每个组件选项绑定透明素材，并声明材质、遮罩和缩放规则。
3. 刻字使用受控字体、最大字符数和安全字符集渲染；不支持任意字体文件。
4. 保存与下单时，后端异步生成统一规格的设计成品图，作为订单留档。

### 报价规则

```text
成交价 = 基础款价格
       + 链条长度加价
       + 材质加价
       + 吊坠/宝石附加价
       + 刻字费用
       + 服务费或人工复核差价
       - 有效营销优惠
```

规则采用可配置条件与固定金额/比例加价，不建议一期允许后台书写任意脚本表达式。所有命中规则须在 `price_breakdown_json` 中留存。

## 9. 底座改造边界

从 platform-wxshop 中保留并复用：

- 微信登录、用户、地址、商品、购物车、订单和支付主流程。
- 管理后台权限、商品管理、订单管理、物流和基础营销能力。
- 数据库初始化、部署脚本、Redis 和支付证书配置结构。

新增或替换：

- 定制商品、组件、素材、规则的数据模型和后台页面。
- 小程序 `designer` 定制器页面与设计方案页面。
- 服务端配置校验、报价、快照、设计图片生成和生产工单服务。
- 定制订单审核、补差价与生产状态流转。

不直接修改支付签名与回调验签、通用库存扣减、权限框架等高风险区域。定制模块通过扩展点接入，避免大范围改写商城核心。

## 10. 实施里程碑

| 阶段 | 交付结果 | 验收标准 |
| --- | --- | --- |
| P0：业务建模 | 产品规则表、工艺字段、页面原型 | 明确首批 5-10 个款式与全部可选组合。 |
| P1：底座落地 | 可运行商城、后台、微信登录和支付环境 | 能浏览商品、创建普通订单并完成支付联调。 |
| P2：定制器 | 2D 预览、选项组合、服务端报价、保存设计 | 每个首发款均可完成配置与准确报价。 |
| P3：履约闭环 | 设计快照、工单、审核、发货与售后 | 每笔定制订单可完整追溯至生产参数。 |
| P4：上线准备 | 隐私合规、监控、备份、素材验收 | 具备提审、灰度发布与异常回滚条件。 |

## 11. 上线前置条件

- 完成小程序主体认证、服务类目和微信支付商户号配置。
- 备案域名、HTTPS、服务器、数据库备份和对象存储策略就绪。
- 商品材质、克重、尺寸、刻字范围、色差说明和售后规则已由业务方确认。
- 支付、退款、库存、价格、订单回调、工单和发货完成测试环境与真实设备验证。
- 开源底座与新增依赖的 LICENSE、NOTICE 和商业使用义务已复核。

## 12. 下一步

先确认首发款式及其定制边界，再将选定商城底座导入独立目录。随后按 P1 到 P3 顺序开发，避免先做 3D 或复杂营销能力导致业务闭环延后。
