## 协议更新与订单行为

新下单、AI准备、手机号授权、短信验证和资料修改检查当前已发布版本是否已确认. 428响应引导到协议确认页, 保留当前页面栈和编辑数据, 不自动重放下单、支付或AI请求. 未发布完整正文时明确提示商家配置缺失.

已有订单查询、继续支付、售后及其他履约流程不因新版本而被整体阻断. 新订单在同一事务冻结两份协议版本及首次确认时间, 订单详情可打开原版本; 网络幂等重试返回原订单, 不再次套用新版本或重复扣库存. 历史订单没有确认凭据时不补造记录.

新登录只交换微信身份, 昵称和头像可在个人中心自愿编辑. 外部微信平台声明、实际账号权限和真机表现仍须由实际环境验收, 项目协议页面不代表平台审核通过.

## 长度配置与界面

制作方式、扣件长度、连接长度、加工缩短量、容差、最小/最大成品长度改为独立毫米表单. 字段保持未知空值, 只有经营者明确填写后才保存完整规则. 不以0代替未配置, 不将测试组合当作正式商家规则.

原材料跨度标为“材料跨度参考”, 与包含工艺参数的成品估算区分. 624宽度截图曾发现嵌套表单标签挤压, 已改为标签在输入上方的响应式网格, 增加实际几何位置断言并复核截图.

## 已有库升级边界

新增`V20261021_01_account_identity.sql`及`V20261021_02_order_legal.sql`. 发布前先备份已有业务库并检查重复身份, 再按迁移工具计划执行全部缺失版本. 本批没有在业务库执行这些脚本, 也没有停止或重建现有服务. 新应用就绪检查要求升级至V20261021_02并具有16张必要表.

本机业务库只读结构比对发现缺少16张表、15个字段, 另有4个字段定义不同, 且未建立迁移台账. 因而不能直接认定旧库已执行哪些迁移, 也不能用空库初始化覆盖现有业务. 具体核对、备份和部署顺序见[业务库升级与部署计划](deployment-plan-2026-10-21.md).

重复身份盘点只读SQL示例:

```sql
SELECT COUNT(*) AS duplicate_groups
FROM (
  SELECT BINARY MA_OPENID AS identity_key
  FROM WX_USER WHERE MA_OPENID IS NOT NULL
  GROUP BY BINARY MA_OPENID HAVING COUNT(*) > 1
) AS conflicts;
```

`OPENID`也须执行相同盘点, 并核对空字符串、历史绑定和标识大小写. 有冲突时停止迁移并人工核对归属, 不直接删除重复行, 不把订单和积分自动搬给另一账号. 既有库只按迁移工具执行V版本, 不执行用于空库的root初始化SQL或重建数据卷.

## 交付流程与外部验收

在干净的已提交源码上执行`python tools/package-commercial-application.py --date 20261021`, 应用包、源码包和manifest均携带提交号. 包内保留许可材料及源码; 构建版本和SHA256以实际生成清单为准, 不将运行中的旧容器当作本次应用已部署.

检查确认20261014、20261016历史应用ZIP中的两个后端JAR均包含application-local.yml. 这些旧包停止用于分发, 保留原文件供核对, 不覆盖或删除. 本批修复资源排除并在最终JAR检查后导出替代包. 未读取或打印该配置内容; 若旧包已对外提供, 应由配置持有人核对并轮换其中可能有效的凭证.

无Git目录的源码规范检查通过source-files.json确定文件范围. 管理端依赖按锁文件准备, Java格式工具按[规范说明](source-style.md)恢复; 增量检查需要Git, 普通交付目录使用默认全量模式. 临时验证目录保留在D:/tmp/hailongcodex/2026-10-21, 本批不删除用户的其他临时文件.
