# 存量源码规范整改记录

本批落实全量格式和小程序静态检查, 对应2026-10-19提出的可读性与统一风格要求. 业务功能仍按已确认的后续计划单独实施, 本记录不将格式通过解释为所有业务和设计缺陷已修复.

## 已完成

- 四个Java模块的全部业务与测试源码使用Google Java Format统一整理, 默认检查从增量改为全量. 当前工作区共610个Java文件, 包含正在实施的商品参数功能源码.
- 管理端业务JS/Vue/CSS/SCSS和小程序JS/WXSS/JSON共294个文件共享根格式配置. 固定两空格、JavaScript单引号和分号, 不再由每个页面自行选择格式.
- 小程序50个脚本接入ESLint, 使用实际微信全局对象, 检查未定义变量、重复字段、无效变量、语法问题和完整条件分支. 使用`const`和`let`替换旧`var`, 两个跨作用域变量另行调整声明位置.
- 为原生小程序具名工具函数和页面入口补充职责说明并增加静态门禁. 清理空生命周期、未使用的页面绑定、搜索页重复排序字段、永远不执行的跳转分支. 分享入口保留, 不按普通空回调删除.
- 将结算共享状态`courseCouponCode`改为`selectedCoupon`, 同步购物车结算、选券、会话清理等实际引用. 修复地址选择保存失败后仍继续返回的问题, 给AI响应解析错误保留原始错误原因.
- 清理旧页面模板提示注释, 移除单个富文本组件与全局格式冲突的局部规则. 原有版权头、第三方DOMPurify、主题原件和许可证不按项目风格改写.

## 后续可读性审查边界

统一格式与静态门禁已经落地. 存量Java实现的职责划分、历史函数注释是否完整准确、复杂页面的函数拆分仍需结合业务整改继续审阅, 不能由格式器自动认定完成. 新改动必须补齐中文职责和关键边界说明, 避免用自动生成的空泛注释凑数量. WXML按微信模板语法维护, 本批未使用HTML格式器改写其标签及绑定.

维护命令和完整范围见[源码规范与检查](source-style.md). 后续交付须运行默认全量命令; `-Incremental`只用于开发过程提速.
