# 项目规范文档

规范版本: 1.0. 更新日期: 2026-10-22. 适用范围为本仓库业务源码、测试、数据库迁移、构建工具及项目文档. 本文规定目标标准, 不表示存量代码已经全部符合; 实际差距统一记录在[项目开发文档](项目开发文档.md).

## 1. 执行与变更规则

1. 用户最新明确要求优先于仓库既有约定. 修改代码前先说明完整计划并取得确认; 已确认范围内持续完成, 不因常规实现选择重复询问.
2. 工作区外文件修改、业务库迁移、停止或重启其他程序须分别取得授权. 构建、启动和部署是三个不同动作.
3. 先确定唯一契约, 同批检查管理端、小程序、服务端、数据库和测试. 重构后统一采用确定的新标准, 不在运行时猜测新旧格式或长期保留两套实现.
4. 历史数据通过明确迁移转换. 无法确定归属、格式或映射时停止并列出冲突, 不猜测、不覆盖. 历史订单冻结内容只用于追溯, 不按当前配置重新解释.
5. 标准变更先更新本文或开发文档中的对应契约, 写清影响及迁移步骤, 再实施代码. 不由一个页面临时决定全项目的数据格式.
6. 不新增未经确认的功能和框架. 优先复用已有公共能力; 不为减少行数堆叠抽象层, 不为兼容旧实现制造分支.

`docs`仅维护四份中文主文档, 文件名不带日期. README提供简介和入口, 不重复承载完整功能状态、部署说明或历次报告.

| 本文 | 代码、协作、测试和交付规范 |

## 3. 编码和命名

- 源码以Google风格为基础, 按用户明确要求所有自有代码统一使用4个空格, 不使用Tab. Java采用Google Java Format的AOSP模式实现4空格, JavaScript、Vue、SQL、Python及C/C++同样为4空格. 格式以仓库配置和固定版本工具为准.
- 文本使用UTF-8. 业务源码使用LF; PowerShell按`.gitattributes`使用CRLF, 含中文且需Windows PowerShell5.1执行的脚本使用UTF-8 BOM. 读取无BOM的UTF-8文件时显式指定编码.
- Java类用UpperCamelCase, 方法/变量用lowerCamelCase, 常量用UPPER_SNAKE_CASE. Java使用显式导入, 不用星号导入、原始集合类型或通过强制转换掩盖契约错误.
- JavaScript优先`const`, 必要时使用`let`; 禁止`var`. 对象方法使用简写, 条件和循环使用完整大括号. 异步业务优先`async/await`, 不使用`that = this`规避作用域问题.
- 名称说明领域含义. 区分goodsId、productId、购物车行ID、设计ID、选项ID和实例ID; 不把名称、数组位置或模糊子串作为身份.
- 新增数据库字段使用snake_case, 由持久化层集中映射. 历史拼写不在各层重复传播, 变更须有完整迁移计划.

## 4. 注释和可读性

所有具名函数、构造函数、接口方法及测试用例必须有中文职责注释, 使用英文标点. 匿名短回调由所属函数说明业务目的; 复杂回调拆成有名称的函数. 重写方法可以引用清楚的接口契约, 实现增加副作用或边界时另作说明.

注释解释业务原因、边界、单位、状态变化和失败处理. 禁止空注释、空生命周期、无效回调、大段注释掉的旧代码及与实际行为不符的说明. 原始版权、作者及许可声明不改写成项目自有声明.

函数围绕一项职责组织. 校验、查询、计算、持久化与响应映射分清边界; 复杂条件提取领域含义清楚的判断. 同一规则由共享实现维护, 不在多个入口复制金额、库存或状态判断.

## 5. 服务端结构

Controller负责认证上下文、协议输入和响应映射. 应用服务负责业务编排、事务及状态迁移. 领域规则负责纯计算和校验. Mapper/DAO负责带归属条件的持久化. Entity不得作为面向客户端的完整用户资料响应.

使用明确的请求DTO、响应DTO及泛型. 用户身份从认证上下文取得, 不信任请求中的userId. Java方法接收并验证明确类型, 不在控制器内展开数据库事务和复杂领域逻辑.

数据库与Redis连接、文件及HTTP资源必须正确释放. 事务覆盖需要一致提交的数据库变更和审计记录. 外部网络请求不占用长数据库事务; 回调、下单、库存、退款需有幂等和并发约束, 不能只靠客户端按钮锁.

异常分为输入错误、权限/归属错误、状态冲突和基础设施失败. 不吞掉关键异常, 不返回堆栈或密钥. 可选辅助展示允许降级, 注释和界面须说明其影响和重试方式.

## 6. 前端和小程序

管理端统一使用原生Vue3、Element Plus和Vite. 不引入Vue2兼容运行时, 不访问组件私有store状态. 公共组件使用`modelValue`和`update:modelValue`, 树、日期、弹窗等使用公开接口.

小程序统一通过公共请求模块访问API. 页面的加载、成功、空内容、失败及重试状态必须完整. 有竞争的请求检查页面代次及账号归属; 旧响应不得覆盖新选择、新账号或已卸载页面. 登录失效统一清理本地及全局身份和私人上下文.

读取失败可以由用户重试. 下单、加购、退款、支付、上传及AI调用不自动重放; 请求中阻止重复提交, 失败释放锁并保留可恢复输入. 游客浏览不得因辅助统计强制触发登录.

展示服务端确认的价格、库存和状态. 客户端只做交互校验, 不作为成交和权限依据. 未知尺寸、规则和商家资料保持未知, 不用0、示例或猜测值补齐.

## 7. 数据与接口

唯一格式和字段单位见开发文档的“数据契约”. 成功响应使用`RestResponse<T>`, `code=0`; 错误同时保持正确的业务码与HTTP状态. 不新增另一种成功码或返回包裹方式. 分页、日期和金额不按调用方喜好临时变换格式.

金额使用BigDecimal及精确十进制, 不用浮点参与可信金额计算. 长度明确使用mm, 显示为cm时只在界面转换. 时间字段必须标明秒、毫秒或带时区文本, 禁止根据数值长度猜单位. BIGINT标识超出JavaScript安全整数范围时必须采用明确的字符串契约.

参数化查询, 数据写入限定用户/商家归属. SQL排序字段、上传类型、URL和状态转换使用白名单. 用户文本默认按文本渲染; 允许HTML的内容通过已核验的净化组件处理.

## 8. 数据库与升级

新增结构和数据转换通过新的V版本SQL. 已记录SHA256的迁移不可修改, 不绕过就绪检查. 根初始化SQL只用于空库; 已有库不执行全量DROP/重建或演示数据覆盖.

先只读盘点、备份并验证恢复, 再在随机隔离库验证升级、失败及重复执行边界. DDL可能部分提交, 失败必须说明修复与重跑步骤. 不自动合并账号、删除不明数据或修改历史交易快照.

## 9. 性能规则

先观察请求次数、查询计划、扫描行数、响应体、首包和交互耗时, 再决定优化. 禁止以关闭校验、隐藏错误、放宽上传上限或提高构建告警阈值换取“性能通过”.

列表必须分页且限制最大页大小. 避免N+1查询、循环访问数据库、无限结果集、重复加载与无效查询. 批量查询维持归属条件, SQL索引依据真实过滤和排序条件设计.

规格组合生成须有数量上限及溢出保护; 选择过程中复用已解析数据, 不反复对每个控件解析全量SKU. 预览和列表限制节点数, 重型前端模块按需加载. 任何性能改善须说明测量条件, 不把渐进复杂度推导冒充实际压测.

## 10. 安全、隐私与许可

秘密只保存在私有配置和受保护挂载, 不提交Git、不输出命令行、不进入JAR、静态目录或交付ZIP. 应用数据库账号与迁移账号分离. 日志不记录令牌、证书、身体参数、地址或支付原文.

图片和视频使用独立安全入口. 校验实际内容、大小、尺寸、归属和路径; 禁止越界覆盖, 禁止图片接口承载脚本或证书. 云存储策略由实际部署环境验证.

新增依赖固定版本并核对许可、来源与分发义务. 保留原LICENSE、NOTICE、版权头和必要对应源码. 当前核验不能视作所有未来版本均已授权; “合规”不代表已经获得平台审核或法律保证.

Java格式工具固定Google Java Format1.28.0并始终传入`--aosp`, 放在`.tools/copyright/google-java-format.jar`, 从官方Maven Central同版本发布物取得并核对SHA256. 前端固定Prettier3.6.2, 使用根`.prettierrc.json`. 具体检查命令见维护文档.

## 11. 验证和完成条件

修改前确定行为边界及验证方法. 修复缺陷须覆盖失败场景、成功恢复及关键并发/权限边界, 不只测试实现中的同一段计算. 低影响格式整理不机械新增镜像式单元测试.

交付前运行全量格式与两端ESLint、适用的Node/Java/Python回归、必要构建及许可核验. 数据库和Redis使用隔离环境. 微信真机、真实支付、AI额度和生产部署单独记录, 不以替身测试代替.

文档工具检查入口、固定中文文件名和本地链接. 初始化源码及迁移生成一致性由tests/python/test_repository_structure.py检查; 两平台摘要对照需设置CARATCRAFT_BASH并提供pwsh, 未提供时明确跳过. 管理端static/config纳入前端格式检查. 新增规范必须说明自动门禁覆盖情况; 未覆盖的规则人工审阅, 不将格式检查通过写成全仓语义已完成.

## 12. 提交与持续维护

提交格式为`类型：中文具体说明`, 类型使用feat、fix、docs、style、refactor、test或chore. 不提交秘密、缓存、target、dist或临时文件. 只提交经过验证的完整改动, 不将草稿测试通过写成最终验收.

正式交付从干净提交导出, 记录提交号、大小和SHA256, 不覆盖旧包. 临时文件使用Windows的`D:/tmp/hailongcodex`或约定平台目录, 创建前检查遗留, 完成后仅清理本次创建的文件. 持久构建记录保存在工作区忽略目录, 不当作临时文件删除.
