## 1. 产品范围

CaratCraft(克拉匠造)为珍珠商城与项链定制项目. 首期四个入口为商城、DIY、社区、我的, 购物车从商品和个人中心进入. 包含二维材料排列、服务端报价、设计保存、订单与工单、售后、协议及基于公开资料和用户实测数据的规则参考. AI能力安排在下一版本, 首版不包含云模型调用及配置入口. 三维颈模、AR、自由建模、多商家和跨境支付不属于当前已确认交付范围.

甲方《珍珠信息合集》需求资料于2026-10-15接收, SHA256为`4cdb7d6266146989ee6bac5fbba25069612578aaa3f27ee3456a6b299c9f1c0f`. 其中问句、示意图、行业知识和其他商家身份不作为已确认生产规则或可发布素材. 品牌、工艺、素材及真实经营资料由经营者确认.

本轮按已确认的两个阶段合并实施. Java工程统一放在`backend/`, 管理端和小程序分别放在`apps/admin-ui/`及`apps/miniapp/`; 部署配置集中到`deploy/`, 数据库只保留`database/init/`完整初始化. 工具按职责归入`tools/`, 跨模块回归归入`tests/`, Java模块测试保留在模块内. `legal/`为唯一许可证据及素材来源入口, 四份主文档继续在`docs/`维护.

目录整理保留Java模块名、包名和HTTP契约. 开发期SQL历史已收敛为最终初始化, 不保留旧迁移链. Compose项目名固定为原默认名`platform-wxshop`, 不因配置目录变化创建另一套默认数据卷. 本轮不执行业务库迁移或服务启停, 不将已有缓存产物当作重构后的构建证据. 旧路径只允许保留未跟踪的本机配置、缓存及运行挂载原件, 不提供源码或运行时双路径兼容分支. 结构变更与业务行为重构分开, 订单查询编排等业务职责调整继续按独立契约实施.

初始化只保留最终结构和必要种子, 六个文件按职责排序, 不再先建旧结构再逐批修复. 当前目录见[仓库结构资料](资料/仓库结构.json). 工具分为quality、database、delivery、legal、assets及maintenance; 跨模块测试分为node、python、powershell、browser及integration. 图示见[系统架构图](资料/架构/系统架构图.mmd)及[时序架构图](资料/架构/时序架构图.mmd).

## 3. 数据契约

### 3.1 标识与标准变更

`goodsId`表示商品, `productId`表示SKU, `specificationId`表示规格组. 页面所用规格值行ID仅用于定位选项, 不得与规格组ID混淆. 交易以服务端验证过的商品和SKU身份为准.

统一采用重构后台的具名SKU组合: `规格组ID:完整规格值`, 组间用`|`连接, 按规格组ID升序生成. 示例为`7:白色|8:8mm`. 无规格仅使用空字符串, 一个商品仅有一个默认SKU. 每组恰有一项, 值不为空且不含分隔符`|`, 不做子串或忽略大小写的匹配. 组合总长度最多2048个UTF-16编码单元, 组合数量最多512, 由SkuContract常量定义; 前端及数据库同步该限制.

旧数字下划线组合只能通过明确迁移转换为上述格式, 运行时不同时接受两种格式. 迁移无法映射的记录须阻断升级并报告. 历史订单保留已成交时的文字和金额, 不改写历史来伪造新格式记录.

商品编辑时保留未改变组合的SKU身份和库存, 不删除重建整套SKU. 已删除或停用的组合不得被另一个组合复用身份. 新组合创建新身份; 改价不改写历史订单.

聚合更新先在事务内锁定主商品并核对存在且未回收, 再修改主表及子项; 不允许仅因主表更新影响行数为0而继续创建孤儿SKU. 同一商品的聚合编辑通过主行锁串行协调, 规格及SKU写入失败时主商品与所有子项整体回滚. 购买入口重新核对当前商品可售状态、SKU归属、价格和库存, 不以编辑表单或购物车旧快照代替成交校验.

### 3.2 金额、数量及尺寸

| 字段/概念 | 唯一含义 |
| --- | --- |
| `number` | 购买件数, 整数1到9999, 合并后仍校验上限和库存 |
| `goodsNumber` | 当前SKU库存, 不能读取SKU数组本身的属性 |
| `retailPrice` | 当前SKU销售单价, 服务端BigDecimal, 客户端仅展示 |
| 实测颈围 | 用户实测值, mm, 不由AI估算覆盖 |
| 目标成品长度 | 商家规则下承诺的目标, mm, 不等同材料跨度 |
| 材料跨度参考 | 二维排列的几何参考, 不作为生产承诺 |
| 工艺成品估算 | 按SUM/OVERLAY_MAX及扣件、连接、缩短量计算, 避免重复计长 |

未知尺寸和工艺参数保持空值, 未满足完整下单条件时可保存草稿但不可下单. 金额使用十进制精度, 时间字段必须明确单位; 现有`addTime`秒时间戳不得被当成毫秒或无时区日期字符串.

### 3.3 HTTP与身份

响应使用`RestResponse<T>`: `success`、`code`、`msg`、`data`、`timestamp`. 成功code为0, timestamp为秒. 400表示输入错误, 409表示状态冲突, 413表示请求体超限, 415表示媒体类型不支持, 401表示会话无效, 403表示权限/归属失败, 428引导确认更新协议; 同时返回相应HTTP状态. 不自动重放被阻断的写操作.

新增和统一后的分页使用page/size请求及records/total/current/size响应, 页大小须有服务端上限. 旧分页接口须先登记调用方后协调迁移, 不让一个接口按客户端种类切换响应结构.

登录、个人资料和公开评价使用白名单DTO. OpenID、IP、运营标签、备注、地址和订单信息不进入公开资料. 账号切换清理全局及本地私人状态, 所有迟到响应核对令牌及页面代次.

当前收藏仅支持商品类型`typeId=0`, 用户归属从认证上下文取得. 切换收藏在业务服务事务内先锁定本人用户行, 再读取及变更本人对应商品记录, 不将查询和写入拆在Controller中. 新增要求商品存在且在售、未回收; 取消允许移除已下架商品的本人收藏, 所有重复行按同一归属条件一并移除. 查询对数值0使用明确的null判断, 不以空字符串比较代替类型校验. 客户端切换动作不自动重放, 接口仍返回本次已完成的add或delete操作.

## 4. 核心流程

### 微信支付 APIv3

直连商户使用微信支付官方 Java SDK `com.github.wechatpay-apiv3:wechatpay-java:0.2.17`. `WechatPaymentGateway` 保持项目自有支付契约, `WechatV3PaymentGateway` 负责官方 SDK 调用. 新交易使用 JSAPI 下单、按商户订单号查单及关单、按商户退款号查询及申请退款. 小程序继续调用 `wx.requestPayment`, 参数使用 RSA 签名. `weixin-java-miniapp` 和 `weixin-java-mp` 继续提供小程序登录和公众号功能. 已移除缺少运行时入口的 `cp`、`open` 以及旧支付模块.

`POST /app/pay/notify` 接收 APIv3 JSON. JSON 通过编码、大小和结构校验后保留原始正文供验签与通知解密, 确认商户、应用、交易状态和金额并完成本地幂等写入后返回 HTTP 204. 退款保留原退款号、唯一约束和领取租约. 渠道超时、验签或内容异常时继续核查, 只有明确查无退款时才允许有提交权限的路径用原号提交. 手动对账只查单. 首发没有真实旧支付订单, 不提供 APIv2 运行分支. 退款结果由主动查询确认.

小程序手机号验证仍调用现有短信适配, 员工找回密码使用独立的管理端流程. 支付宝保留原适配, 首发商城结算使用微信支付. 本机实际上传为磁盘模式, 管理端和 API 挂载同一上传卷, Nginx 只读提供 `/upload/`. 小程序用当前 API 来源解析相对资源地址.

### DIY材料目录唯一契约

本轮客户需求补齐范围已确认. 新配置仅使用pearl(珍珠)、clasp(尾扣)、accessory(配饰)、chain(链条)四类, 必选组也只能从四类选择且不重复. 贵金属材质、款式和候选尺寸作为材料属性, 不再作为可售组件类别. 配饰必须明确lengthRole=INLINE(串接, 按spanMm计长)或HANGING(悬挂, 不占周长), 未确认前只能停用保存, 未知计长位置或串接跨度阻止下单; 位置随排列和报价冻结. 扣件长度仍由统一工艺规则计入, 不重复累计. 旧类不按名称猜测归类; 新增受控迁移停用旧类及受影响的定制模板, 保留选项、库存流水、设计和已成交快照, 商家重新确认后按四类建立新配置. 不对业务库自动执行迁移.

客户候选目录使用单一JSON来源, 包含67项珍珠候选(含巴洛克待实测项)、4项尾扣及27项链材组合. 后台可取得完整导入模板, 初始化入口由同源生成器生成候选, 已存在V迁移禁止覆盖, 后续目录调整须新增资源版本和迁移; 候选默认停用、零库存, 未知价格及尺寸须商家确认, 不将区间中点写入实测直径, 不携带参考商家图片. 用户已授权自主处理配饰拆分, 据原文形成14个暂定名称候选; 戴妃皇冠与皇冠分别保留, 原文及暂定标记随模板保留, 商家发布前核对. 全目录共112项. 微信小程序官方编译及页面验证在本轮实际执行后记录结果, 不以Node脚本替代编译结果.

- 商品: 后台维护来源/品类、事实参数、SKU、价格库存及媒体; 保存后小程序组合筛选与详情一致. 未删除且在售并具备必要分类的商品才进入新目录, 公开商品总数同样排除已删除及下架商品. 请求不存在的分类返回明确输入错误, 不再触发空指针.
- 定制: 四类材料按稳定实例顺序编辑, 服务端累计用量、校验必选和库存、重新报价; 保存更新本人草稿并校验版本. 下单冻结材料、尺寸、工艺、价格及条款版本.
- 交易: 立即购买生成本人独立上下文; 结算和提交再次校验SKU及价格. 下单幂等、库存事务、支付回调和退款对账各有服务端约束. 取消或未发货退款逐行核对SKU库存恢复结果, 任一商品恢复失败即抛出异常并回滚订单状态; 未使用优惠券时释放0行属于正常情况. 客户端成功提示不代替服务端支付结果.
- 生产: 审核、制作、质检、发货按状态机流转, 操作和原因可追溯. 不允许通过任意状态文本跳过环节.
- 社区: 设计/成品/建议发布后待审核, 只有公开内容可浏览和点赞. 设计使用公开副本, 不公开私人刻字、身体参数和订单. 不开放评论、私信或好友.
- 协议: 完整初始化提供用户协议和隐私政策正式首版, 两者kind分别为TERMS/PRIVACY, version均为1, 随新环境部署. 后续每次保存生成递增修订号, 发布使用新版本且不覆盖已发布正文; 用户确认当前版本, 新交易冻结版本, 已有订单履约不因新条款被整体阻断. 经营者正式主体及联系方式仍需核实, 补充时同样升级版本; 未发布正文不补造确认记录.
- 规则参考: 首版由platform-biz读取商家有效配置, 结合用户选填实测颈围和较短/中等/较长偏好, 筛选可比较的常见长度, 同时列出单项库存可用的材料供手动选择. 不调用模型、不采集身高体重、不生成或消费AI票据; AI在下一版本重新评估.

定制库存只接受服务端冻结的完整`components`清单, 以`componentType`、`optionCode`和整数`quantity`扣减或恢复并记录流水. 全部清单行先校验后变动库存; 缺失、损坏、重复身份及非整数用量均阻断事务, 不再按旧optionIds回退到每项1件. 零用量表示已明确配置的虚拟材料, 不写库存流水. 当前未发布开发数据按现有初始化及重新保存草稿生成标准快照, 无需维护旧格式运行分支; 上线后的冻结内容不得按当前选项配置猜测转换.

### 首版参考规则契约

`POST /app/customization/reference`只接收goodsId、选填neckCircumferenceMm和preference(SHORT/MEDIUM/LONG), 用户身份从认证上下文取得. 颈围以mm计, 有值时范围200到800、最多1位小数; 不通过身高体重或网络人群均值估算. 数据仅用于本次筛选, 不另存个人身体画像.

固定资料为[Tiffany官方项链尺寸指南](https://www.tiffany.com/client-services/size-guide/necklaces-pendants-size.html), 核验日期2026-10-28. 公开长度40.50/45.75/50.75/61.00cm转换为405/457.5/507.5/610mm. 项目将相邻两档分为较短、中等、较长供比较, 此分组是产品交互规则, 不是资料给出的个体合身公式. 过滤掉不大于实测颈围的长度, 有商家长度规则时再按可制作上下限筛选; 无交集明确显示无参考值, 不抬高、补造或自动改换偏好. 没有实测颈围时只展示通用比较值及测量提示. 返回资料来源、规则标识、参考值及筛选理由.

材料候选仅来自当前商品启用选项, 按实际单项用量核对库存; 零用量的虚拟材料无需库存余额. 候选不表示组合兼容或可下单, 不自动选择材料、数量或成品长度. 用户继续排列后仍由既有报价、工艺长度和库存服务统一验证. 规则参考不依赖云环境、Redis票据或第三方模型. 首版删除旧AI运行源码和相关测试, 下一版本从Git历史续接, 不保留并行实现.

### 员工临时密码和找回

新设密码为 6 到 32 位可打印 ASCII 字符. 新开户至少填写手机号或邮箱, 服务端设置统一临时密码. 管理员重置同样标记员工须改密. Shiro 每次认证读取该状态, 临时会话只允许本人改密及退出. 改密后撤销旧会话. 已有账号密码继续有效.

普通员工通过管理端两个找回接口发码与重置, 发送地址来自员工档案. 图形验证码及 Redis 限流防止滥发, 六位码五分钟有效并限制五次尝试. 验证码绑定账号、当前联系方式和密码哈希. 修改联系方式或密码使旧码失效. 找回不签发会话, 系统管理、应急管理员和资金写操作岗位走已授权的人工重置流程.

### 单工作室导航及开户

服务端按 `CARATCRAFT_DEFAULT_BUSINESS_ORG` 选择新员工所属机构, 并检查机构状态与调用者的开户、分配角色权限. 配置缺失或失效时拒绝开户, 写请求试图改变归属时拒绝. 员工编辑沿用已有归属. 机构仍由应急管理员在角色管理页的“组织机构维护”入口维护.

管理端按服务端菜单生成工作台、商品与材料、订单与制作、客服与售后、社区及系统设置. 隐藏空分组, 保留获准的受控工具直接访问. 退款管理仍使用独立读取和操作权限. 登录切换后清理上一账号的动态路由. 订单详情、商品详情和编辑、员工新增和编辑采用独立子路径, 列表条件及页码保存在 URL. 员工和商品表单仅在存在未保存改动时提示离开.
